## 卡点完整排查链（别重走）

错误：会话发消息 → `DSH permission preset service is unavailable`（`DSH_PERMISSION_UNAVAILABLE`）。

**抛点**：`src/dsh/context.ts` 的 `resolveDshContext` fail-closed 链：sessions → workspaceRegistry（workspace 匹配）→ sandboxPolicy → permissionPresets，逐级硬校验。**实测前四关全过（inject 修复生效），唯独第五关拿不到服务。**

已排除（每一项都有实证，别再猜）：

| 假设 | 排除证据 |
|---|---|
| 服务名不对 | 官方包 `@deepseek-ai/dsh-permission-presets/lib/index.js:110` 实锤 `super(ctx, "permissionPresets")` |
| cordis get 抛异常被吞 | 诊断钩子（`service()` catch → `%TEMP%\dsh-agy-provider-context-diag.log`）零记录——`get()` 不抛，**静默返回 undefined** |
| root 作用域可见 | `context.root?.get()` 兜底后依旧 undefined |
| 代理/网络 | keyring 续期日志实锤通（`expiry=2026-10-12 14:08, expired=false`，无 timed out）——失败发生在权限校验层，未到网络步 |
| inject 机制失效 | 同一名单五个服务里 sessions/workspace/sandbox 三关都过了，机制是好的 |

**已验证的宿主事实**（asar 只读解包到 `F:\AgentData\work\tmp-antigravity-survey\dsh-asar\`）：
- 服务包在宿主：`dsh/node_modules/@deepseek-ai/dsh-permission-presets/` 存在，且是 `dsh-base` 的 dependency；
- **但 desktop profile 的 bundles 清单（17→18 条）里原本没有它**——cordis 的服务只在插件被 loader apply 时 provide，**未装载 = 未实例化 = get 不到**；
- 对照组：同 inject 名单的 sessions/workspace/sandbox 都有装载点，唯独它没有。

**已部署的修复（未验证）**：bundles 显式加 `@deepseek-ai/dsh-permission-presets`（插在 `@deepseek-ai/dsh-base` 后）→ 宿主已重启（14:07:53 就位）。用户发了消息但验证读数被中断。
